# @samline/scroll-to

Build against the installed version; this skill describes 1.5.0.

- **Install:** `npm install @samline/scroll-to`. Plain HTML: load `https://cdn.jsdelivr.net/npm/@samline/scroll-to@1.5.0/dist/browser/scroll-to.global.js`; it handles same-page `#id` links and `[data-scroll-to]` on its own (`data-manual` on the script tag, then `ScrollTo.auto(options)`, to pass options). No stylesheet.
- **Markup:** plain `<a href="#id">` links, or any element with `data-scroll-to="#id" | selector | top`. Per-trigger attributes: `data-scroll-to-offset`, `-container`, `-block`, `-inline`, `-duration`.
- **Script:** `autoScrollTo({ offset, container, block, inline, duration, easing, behavior, interruptible, focus, hash, signal, onStart, onProgress, onEnd, selector, scope, initialHash })` returns `{ destroy }`; `await scrollTo(target, options)` resolves `true` on arrival, `false` when interrupted or replaced; `scrollPosition(target, options)` measures only; `cancelScroll(container)`; `isScrolling(container)`.
- **Lifecycle:** `onStart(detail)`, `onProgress({ progress, eased, ...detail })`, `onEnd({ arrived, reason, ...detail })` with `detail = { target, container, trigger, top, left }`; `reason` is `arrived | interrupted | replaced | cancelled | missing`, and `onEnd` runs exactly once (after focus/hash). `signal: AbortSignal` stops it (`cancelled`). Bubbling `scroll-to:start` / `scroll-to:end` events on the target (or the scrolling element for positions/missing). `data-scroll-to-state="scrolling"` on `<html>`/the container and the clicked trigger while running; `isScrolling(container)` tells scripted scrolls from the visitor's.
- **Defaults:** `createScrollTo(defaults)` returns `{ to, position, cancel, isScrolling, auto, destroy }`; per-call options replace defaults key by key; `destroy()` (idempotent) stops only its own scrolls and `auto()` controllers.
- **Aim:** `offset` also takes `'auto'` (fixed elements at the top edge and anything stuck below them, plus sticky elements with a `top` that precede the target as siblings of it or its ancestors, counted at their stuck position; ignores elements taller than half the container), `'css'` (container `scroll-padding-top` + target `scroll-margin-top`), a function `({ container, target }) => px`, or an array (summed); offsets apply to elements only. Targets: `'bottom'`, `'+=400'`/`'-=50%'` (% of container height, fixed at start), `{ top, left }` points (`left: '+=100%'` pages a strip). `when: 'needed'` skips the move if the element is fully visible (still `arrived`, focus/hash run).
- **Sections:** targets `'next'`/`'prev'` step through `sections` (default `'section'`, in the container) by comparing destinations with the offset/alignment; unreachable or hidden sections are skipped; a press while a scroll heads to a section steps on from it; nothing left → `missing` and the click is left alone. `reveal` (default `true`) opens closed ancestor `<details>` (not when the target is in their summary) and `hidden="until-found"` ancestors (dispatching `beforematch`) before scrolling; `scrollPosition` never mutates. Trigger attributes `data-scroll-to-sections`, `-focus`, `-hash` (`push|replace|false`), `-reveal`.
- **Feedback:** `highlight: true | ms` (1500 by default for `true`) sets `data-scroll-to-arrived` on the target element after an `arrived` end only (also when already in place; restarted on a new arrival; also under reduced motion); trigger attribute `data-scroll-to-highlight` (empty/`true`/`false`/ms). While animating, `--scroll-to-progress` (eased 0–1, inline style) sits on the scrolling element and the trigger, removed at the end. `backToTop(button | selector, { target = 'top', threshold = '100%' | px | '%', focus = true, ...scrollOptions })` returns `{ update, destroy }`: `data-scroll-to-visible="true|false"` (never set before JS, so hide with `[data-scroll-to-visible="false"]` + `visibility: hidden`), `--scroll-to-scrolled` 0–1 on the button, its click prevents default (autoScrollTo skips it) and, if the button had focus, moves focus to the target element or the container/`<body>` (temporary `tabindex="-1"`). The browser bundle turns `[data-scroll-to-back-to-top="threshold"]` into buttons; `ScrollTo.controller.destroy()` stops them.
- **Timing:** `duration` number wins; else `speed` (px/s) or the auto rule (distance/2, 300–1000 ms); `maxDuration` caps auto/speed. `easing`: `linear`, `ease-in`, `ease-out`, `ease-in-out`, `ease-out-quint`, `ease-out-back`, `'cubic-bezier(x1,y1,x2,y2)'` (x within 0–1) or a function; `cubicBezier()` is exported. Attributes `data-scroll-to-speed`, `-easing`, `-when`; `-offset` accepts `auto`/`css`.
- **Semantics:** `offset` takes px, `%` or an element/selector whose height is used; destination re-measured each frame; the wheel, touch, scrolling keys (arrows, Page Up/Down, Home, End, Space) and mouse presses outside links/buttons/controls interrupt (Tab, Enter and clicks on triggers do not, so a Stop button needs `cancelScroll()` or a `signal`); reduced motion jumps. `autoScrollTo` defaults to `focus: true` and `hash: 'push'`; plain `scrollTo` changes neither unless asked.
- **Containers:** `container: 'auto'` (also `data-scroll-to-container="auto"`) scrolls every scrolling ancestor of the target (overflow auto/scroll/overlay with room; stops below `<body>`) innermost first, then the page if it can scroll, in one animation re-measured each frame; `offset` applies only to the outermost container; `when: 'needed'` per container; positions/`'top'` use the page; callbacks report the innermost `container`; `cancelScroll()`/`isScrolling()` work on any of them; `scrollPosition` returns the innermost. `scroll-snap-type` is set inline to `none !important` on moving containers and restored at the end (align targets on snap points to avoid a re-snap). Frames use `behavior: 'instant'`, so CSS `scroll-behavior: smooth` is harmless. RTL (container `direction`, page from `<body>`): `inline: 'start'` = right edge, `'next'` goes left, `left` values are `0..-max` like `scrollLeft`, relative `left` moves are physical (`'-=100%'` is forward). A target already in place arrives without calling `scrollTo` on the container.
- **Layouts:** pass `container` for scrolling boxes and `inline: 'center', block: 'nearest'` to center tabs in a strip; add `scroll-padding-top` in CSS for jumps the script does not handle, and pass `offset: 'css'` so the script reads the same value instead of duplicating it.
- **Do not** poll `scrollY` to detect the end of a scroll (use `onEnd` or `scroll-to:end`), or wrap `scrollTo` in a timeout to cancel it (use `signal`). **Do not** add another click handler that calls `scrollIntoView` on the same links, compute offsets with `offsetTop` yourself, or use `<span>` click targets where a link works.
